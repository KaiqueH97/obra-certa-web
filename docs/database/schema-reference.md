# Estrutura informada do Supabase

Referência recebida do Schema Visualizer em 07/09/2026. Os escapes de Markdown
foram removidos e as tabelas foram ordenadas pelas dependências.

Este documento não é uma migration e não deve ser executado sobre as tabelas
existentes. Ele não inclui políticas RLS, grants, triggers ou índices adicionais.
Nenhuma alteração no banco foi aplicada a partir desta referência.

```sql
create table public.projetos (
  id bigint generated by default as identity not null,
  titulo text not null,
  user_id uuid not null,
  criado_em timestamp with time zone not null default timezone('utc'::text, now()),
  constraint projetos_pkey primary key (id),
  constraint projetos_user_id_fkey foreign key (user_id) references auth.users (id)
) tablespace pg_default;

create table public.funcionarios (
  id bigint generated by default as identity not null,
  nome text not null,
  cargo text null,
  valor_diaria numeric(10, 2) null default 0.00,
  user_id uuid not null,
  criado_em timestamp with time zone not null default timezone('utc'::text, now()),
  constraint funcionarios_pkey primary key (id),
  constraint funcionarios_user_id_fkey foreign key (user_id) references auth.users (id) on delete cascade
) tablespace pg_default;

create table public.tarefas (
  id bigint generated by default as identity not null,
  projeto_id bigint not null,
  nome text not null,
  concluida boolean null default false,
  criado_em timestamp with time zone not null default timezone('utc'::text, now()),
  constraint tarefas_pkey primary key (id),
  constraint tarefas_projeto_id_fkey foreign key (projeto_id) references public.projetos (id) on delete cascade
) tablespace pg_default;

create table public.materiais_projeto (
  id bigint generated always as identity not null,
  projeto_id bigint not null,
  user_id uuid not null default auth.uid(),
  nome text not null,
  quantidade text not null,
  criado_em timestamp with time zone not null default timezone('utc'::text, now()),
  preco_total numeric null default 0,
  constraint materiais_projeto_pkey primary key (id),
  constraint materiais_projeto_projeto_id_fkey foreign key (projeto_id) references public.projetos (id) on delete cascade,
  constraint materiais_projeto_user_id_fkey foreign key (user_id) references auth.users (id)
) tablespace pg_default;

create table public.financeiro_obra (
  id bigint generated by default as identity not null,
  projeto_id bigint not null,
  tipo text not null,
  valor numeric(10, 2) not null,
  data date not null default current_date,
  funcionario_id bigint null,
  descricao text null,
  criado_em timestamp with time zone not null default timezone('utc'::text, now()),
  constraint financeiro_obra_pkey primary key (id),
  constraint financeiro_obra_funcionario_id_fkey foreign key (funcionario_id) references public.funcionarios (id) on delete set null,
  constraint financeiro_obra_projeto_id_fkey foreign key (projeto_id) references public.projetos (id) on delete cascade,
  constraint check_tipo_transacao check (
    tipo = any (array['RECEBIMENTO_CLIENTE'::text, 'PAGAMENTO_FUNCIONARIO'::text])
  )
) tablespace pg_default;
```

## Próximo diagnóstico

Executar somente o conteúdo de [diagnostico-rls.sql](./diagnostico-rls.sql)
no SQL Editor do Supabase. A consulta lê metadados: habilitação de RLS,
políticas (inclusive USING e WITH CHECK) e privilégios efetivos de tabela
para `anon` e `authenticated`. Ela retorna uma linha por tabela encontrada.

Os privilégios de tabela não substituem RLS; a consulta não comprova, sozinha,
isolamento entre contas. Grants por coluna, funções auxiliares e triggers podem
exigir inspeção complementar conforme as políticas encontradas.
